A construction tool, built around site reality.

The goal is useful scheduling for working engineers and project managers—not pretending that a prototype is already a complete Primavera replacement.

01 / The problem

Plans break when reality changes

Crews are shared, materials arrive late, activities depend on prior work and each site runs to a different working calendar. A schedule should expose those constraints, not hide them.

02 / The product

A practical browser scheduler

Enter work activities, assign labor and equipment, set dependencies and press Schedule. Review allocated work days, Gantt bars and resource delays.

03 / The direction

Your construction experience, encoded

Future versions should connect quantities, work packages, productivity, actual site progress, baselines, reports and lessons learned—with traceable source data.

Start here / 3-minute walkthrough

From activity list to resource-leveled plan

Step 1

Define your work

Start with the synthetic excavation → PCC → reinforcement / formwork → footing RCC → waterproofing example. Change activity names, durations and dates.

Step 2

Assign constraints

Set crew capacity, resource assignments, material inventory and FS/SS/FF/SF predecessor links. Shared capacity causes a scheduling trade-off.

Step 3

Press Schedule (F9)

Inspect allocated Gantt days, finish events and delayed activities. Save a local draft or export versioned JSON as a portable record.

What exists today / v0.4.3

One repository, four distinct tools

TESTED KERNEL

1. Scheduling core

Custom JavaScript algorithms for CPM and float, calendars, lagged dependency logic, selected constraints/progress calculations, and serial resource leveling. Capabilities differ by API path.

INTERACTIVE PROTOTYPE

2. Live Scheduler

Editable unstarted resource-dependent activities, assignments, durations, capacity, and serial day-level scheduling. No server/database or automatic shared saving yet.

EXPERIMENTAL

3. Engine Lab

A separate synthetic CPM/remaining-work testing surface with data-date controls, constraints, earned value, and adapter previews. It is not the same unified engine path as the planner.

SHAREABLE REFERENCE

4. Field knowledge

Separate shuttering, waterproofing and research-gated soak-pit pages to connect scheduling concepts to work methods and QA—without confusing guidance with project authority.

NOT YET COMPLETE

5. Baseline + progress

Scheduled snapshots, daily site updates, variance analysis, lookahead plans, manpower and material reports are still planned as an integrated workflow.

NOT YET COMPLETE

6. Real project system

Authenticated multi-project database, roles, durable collaboration, spreadsheet/P6 interoperability and BIM/4D are separate future milestones.

Data contract / inputs

What you need to build a reliable construction schedule

Now / minimum
Project start and working days; activity IDs, descriptions, work-day durations; predecessor/successor logic; labor/equipment/material resources and assignments.
Now / availability
Capacity and stock, plus resource/crew calendars and material receipts or fixed reservations through supported engine JSON. All examples are synthetic.
Next / construction intelligence
WBS, BOQ quantities, work package IDs, measured productivity, site zones, subcontractors, material deliveries and constraints in the actual planning workflow.
Next / live control
Baseline dates, data date, actual start/finish, remaining duration, field progress, variance, delay causes, site photos, reports and audit lineage.
Practical example: Two crews both need the only available concrete mixer. Instead of scheduling both at once, the serial leveler moves the conflicting work into an available day and explains the delay. This is a deterministic rule, not a claim of optimal project duration.

The five upstream ecosystems actually recorded in this repo

The source code is currently a custom ES-module scheduling kernel. These five projects are recorded as references, adapters or future integration targets in UPSTREAM_SOURCES.json—their entire codebases have not been incorporated or bundled.

CPM, resources, float, baselines and familiar desktop planner workflows.

Resource-constrained planning, scheduling policies and scenario comparisons.
