One schedule. Four consistent views.

This studio reads the same calculated project model for an organic, upward-growing WBS skill tree, Gantt, calendar and checklist. Change the project, and the WBS and views change together—without inheriting Narayani's activity list.

Safety: Both included projects are deliberately synthetic. Durations are assumed, all approvals remain false, and the calendar shows scheduled events rather than actual daily construction progress. A locally selected compiled model stays in your browser and is never uploaded.

Generic digitalization: import an explicit-schema CSV/TSV work-item table, the project WBS task-seed JSON (even if saved as .md), local unverified canonical project JSON, or previously compiled safe view model. Optionally select a matching WBS dictionary to preserve genuine phase names. Your original files stay on your device. CSV header: activity_id,activity_name,wbs_id,wbs_name,parent_wbs_id,duration_slots,predecessors. The predecessor cell uses quoted ID:FS:0;ID:SS:2 syntax; empty fields are allowed for root WBS and no predecessor. Missing durations block dates. Unmapped calendar IDs block scheduling. Excel, P6 XER/XML and PDF still need audited converters; export a structured CSV rather than claiming unsupported fields were imported.
