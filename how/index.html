1. The core principle: precedence network and CPM

Each activity has a stable ID, duration and source-owned WBS parent. Directed FS, SS, FF and SF relationships impose mathematical constraints. The forward pass calculates earliest dates, the backward pass calculates latest dates, and float identifies schedule sensitivity under an explicit finish requirement.

2. The five interlocking engines

WBS → scope spine

One hierarchical work package decomposition, stable foreign keys and explicit rollups. A sum of activity durations is not the project critical-path duration when tasks overlap.

Calendars → real clock

Project day pattern, weather/activity calendars, resource availability and holiday exclusions. Curing may follow a continuous clock while a construction crew does not.

Precedence/constraints → physics

Typed dependencies, signed lag and applicable scheduling constraints. Dangling IDs, cycles, impossible or unsupported time modes must fail instead of guessing.

Resources → capacities

Labor in person-hours, equipment in machine-hours and materials in real quantities. A receipt or shortage must change calculated availability rather than a manually colored bar.

Baseline & actuals → evidence

Approved schedule/cost snapshot versus immutable, sourced actual events; never promote a Slack report to structural acceptance, approved payment or construction release.

AI adapters → project identity

New school, hospital or residence brings its own WBS, BOQ, calendars, resource units and assumptions—while retaining the validated engine laws and provenance contract.

3. Earned value without invented actuals

PV measures approved baseline value planned to date, EV is the budgeted value of verified completed work, and AC is governed actual cost. Schedule and cost ratios are different questions from physical critical-path lateness.

SV = EV − PV CV = EV − AC SPI = EV / PV CPI = EV / AC When a denominator is zero → undefined, not fabricated.

4. Reproduce a new project's product without hallucinated principles

  1. Discover authorities: exact project ID, source register, last control checkpoint, engine version, approved and open revision registers.
  2. Decompose the real project: WBS/activities from zones, trade packages and designed physical sequence—not the Narayani 45-task template.
  3. Record parameter provenance: geometry, design loads, crew units, resource receipts, calendars, cost rates, delivery constraints, source revision and units.
  4. Calculate justified missing measurements: show formulas and source inputs. Tag scenario assumptions ASSUMED_DRAFT; never silently invent structural safety or issue-for-construction dimensions.
  5. Normalize and enforce PK/FK: project → WBS → activity → predecessor/resource/calendar. Detect duplicate IDs, invalid units, cycles and unavailable materials.
  6. Use the pinned actual engine: invoke CPM/calendar/resource functions; build derived Gantt, calendar and constellation from one validated source, not independently authored dates.
  7. Review invariants: re-run tests, scheduling oracle, quantity/unit checks, holds, source hashes, source read-back, public/private boundaries.
  8. Tag every output: APPROVED only with authoritative signoff; otherwise CALCULATED_DRAFT, REPORTED, ASSUMED_DRAFT or HOLD.
  9. Release with rollback: record input and output SHA-256, exact Git commit, engine adapter version, test evidence, outstanding debt and prior deployment.
**100/100 reproduction means deterministic behavior given identical validated sources, parameter contracts, calendar/timezone and engine commit.** It does not mean assumptions are true, that an activity list is universally applicable, or that every P6 feature already exists.

Why not simply type dates into a spreadsheet?

Dates and downstream impacts must be computed from WBS, dependencies, calendars, resources and constraints. Manual dates do not guarantee network consistency.

Does a green-looking node mean engineering acceptance?

No. Reports, approvals, permits and structural holds are separate governed authorities; public synthetic status is not signoff.

What does exact reproduction mean?

Pin engine commit, inputs, units, effective revisions, calendars, assumptions, algorithms, hashes and test evidence. Different projects keep the laws and change their parameter set.

What if a dimension is absent?

Derive only what the available source supports; otherwise record explicit assumption and scenario impact, never an approved structural quantity.

What is SPI and why is it not the same as CPM delay?

SPI = EV/PV is budgeted-value schedule performance. Finish-delay analysis also needs the actual driving dependency network and updated calendars.
