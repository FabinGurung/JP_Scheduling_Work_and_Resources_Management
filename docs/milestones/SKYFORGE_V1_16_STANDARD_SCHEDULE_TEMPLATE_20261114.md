# Skyforge v1.16 — Cross-project normalized schedule-template milestone

Release classification: standard source contract, project-independent edition comparison, machine tests and Pages distribution. **NOT** engineering approval, verified site progress or a construction baseline.

## Achievement

Narayani v002 (160 activities, 210 links, 156 timed, 6 holds, relative-week reference) and Harisharan v002 (839 activities, 1,321 links, dated 2026-11-16, 18 preliminary source-graded labour estimates and project-specific engineering holds) already share a Gantt/calendar renderer. This milestone supplies the missing reusable new-project intake contract and cross-project normalization without copying either project's schedules into the other's working data.

- `src/kernel/standard-schedule-template.mjs`: semantic validator, deterministic source intake, common comparison edition adapter and cross-project summary. Unknown quantities, time bases and source references stay explicit; cycle and unsupported release claims are rejected.
- `schemas/standard-schedule-input.schema.json`: portable machine-readable JSON Schema for future project source intake.
- `templates/scheduling/standard-schedule-input-v1.example.json`: downloadable public-safe template exposed in Studio; no private client data.
- `templates/scheduling/edition-comparison.json`: autogenerated read-only comparison from validated existing Narayani v002 and Harisharan v002 project models during site build.
- `tests/standard-schedule-template.test.mjs`: full acceptance/regression tests using both actual project datasets and an independent synthetic second project.
- `docs/architecture/SKYFORGE_STANDARD_SCHEDULE_TEMPLATE_V1_20261114.md`: detailed A9 handover and project reuse policy.

## Version policy

1. Preserve previous `v1.15.0-skyforge-sheets-materials.1` milestone and original Narayani 45-activity pilot.
2. Keep Narayani v002, Harisharan V000001, Harisharan v002 and Harisharan V003 as separate source/derived editions; do not overwrite them.
3. Each new project starts from the generic source template with a verified project identity and its own Drive authority.
4. Nepali original and English working translations are linked through `source_manifest`, but full private text stays in the controlled Drive project folder. English can be the working extraction/derivation source after traceable verification, not a destructive replacement for the original.
5. Reuse the existing scheduling kernel, Work Output Planner and Materials Planner as separately source-graded references **only when unit and applicability checks permit**; no automatic M20 ingredient assumption for structural M25 or unsupported rate/unit conversions.
6. No universal measured quantities, crew bookings, contract dates, construction acceptance or material orders have been inferred.
